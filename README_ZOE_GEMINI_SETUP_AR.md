# تفعيل «زوع» وربطه ببيانات Mojam Office

## ما الذي تغيّر؟

أصبح مسار `/api/chat` يرفق حقائق تشغيلية يسترجعها الخادم مباشرة من MongoDB قبل طلب الرد من Gemini:

- **الأسعار:** آخر أسعار بورصة محفوظة في اليومية، مع تاريخ تسجيلها.
- **المخزون:** المتبقي لكل صنف محسوبًا من رصيد بداية اليوم + المرتجعات + كميات كروت الشحنات − كميات فواتير اليوم.
- **العميل المرسل:** عند السؤال عن حسابه أو الصناديق أو فواتيره، تتم مطابقة رقم هاتف المرسل مع سجل Mongo. لا يُرسل رقم الهاتف إلى Gemini.
- **فواتير العميل:** آخر خمس فواتير مطابقة في اليوميات المحفوظة، مع الصنف والكمية والإجمالي والصناديق الفارغة المستلمة.
- **الصناديق:** إذا كان سجل العميل يحتوي `total_delivered` و`total_returned`، يُحسب المتبقي عليه منهما. لا يستنتج النظام صناديق العميل من كمية الدجاج.

إذا لم توجد معلومة موثوقة في قاعدة البيانات، يُطلب من زوع التصريح بذلك بدل اختراع سعر أو مخزون أو رصيد. **الرصيد المالي الصافي** لا يمكن حسابه من فواتير الآجل وحدها؛ يلزم تسجيل الدفعات/السداد في دفتر مالي. سيستخدم النظام حقل رصيد صريحًا للعميل إن كان موجودًا، وإلا لن يعرض مجموع فواتير الآجل كأنه دين قائم.

تُحفظ الأسعار مع اليومية في `daily_sessions.payload.dailyPrices`. بعد نشر التحديث، افتح التطبيق، أدخل أسعار البورصة واضغط حفظ الأسعار/اليومية مرة واحدة ليتم مزامنتها. تبقى واجهة الفاتورة والطابعة الحرارية والحفظ في التكدس كما هي.

## النموذج والمفتاح

يستخدم الخادم `gemini-3.5-flash-lite` افتراضيًا. لا تحتوي ملفات التحديث على مفتاح API.

1. أنشئ مفتاح Gemini من [Google AI Studio](https://aistudio.google.com/apikey).
2. في Render افتح خدمة `mojam-office-api` ثم **Environment**، وأضف `GEMINI_API_KEY` في خانة Key والمفتاح في خانة Value. ويمكن إضافة `GEMINI_MODEL=gemini-3.5-flash-lite` اختياريًا.
3. احفظ التغييرات وانتظر إعادة نشر الخدمة.
4. للتشغيل المحلي، يكون الملف `server/.env` بجوار `package.json`، وليس `server/src/.env`.

لا تضع `.env` أو المفتاح في GitHub، ولا تضع المفتاح داخل `public/index.html`. إذا سبق رفع مفتاح حقيقي إلى مستودع عام، أبطله وأنشئ مفتاحًا بديلًا.

## رفع ملفات التحديث من Termux

من جذر المشروع الذي يحتوي مجلد `public` ومجلد `server`:

```bash
cd ~/projects/mojam/مكتب_معجم_حزمة || exit 1
unzip -o /storage/emulated/0/Download/mojam_zoe_mongo_context_update.zip -d .
git status --short
```

ثم أضف **الملفات الستة غير السرية** وارفعها:

```bash
git add public/index.html public/invoice-manual-cards.js \
  server/src/server.js server/src/gemini.js server/src/business-context.js \
  README_ZOE_GEMINI_SETUP_AR.md

git diff --cached --check || exit 1
if git diff --cached --name-only | grep -Eq '(^|/)\.env$'; then
  echo 'توقف: يوجد ملف .env ضمن الملفات المضافة؛ لا ترفعه.'
  exit 1
fi

git commit -m "Connect Zoe to Mojam MongoDB business data"
git push origin main
```

سيؤدي الدفع إلى `main` إلى بدء النشر في Render إذا كان الربط التلقائي بالمستودع مفعّلًا. **لا تشغّل `seed-admin`** لهذا التعديل.

## اختبار آمن بعد النشر

1. انتظر اكتمال نشر Render، ثم افتح التطبيق وسجّل الدخول.
2. في شاشة الأسعار، أدخل الأسعار الصحيحة واحفظها حتى تظهر رسالة حفظ اليومية في السيرفر.
3. جرّب يدويًا أولًا أسئلة مثل: «كم سعر الكبير؟» و«كم باقي من صنف كبير؟» ثم من محادثة عميل مطابق: «كم علينا شبوك؟» أو «ما آخر فاتورة؟».
4. راجع الرقم والتاريخ في الرد، وتأكد من وجود سجل الصناديق للعميل قبل الاعتماد عليه.
5. اترك الإرسال التلقائي متوقفًا حتى تجتاز الاختبارات وتراجع الأجوبة؛ بعدها فعّله فقط إذا كانت بيانات الأسعار والمخزون والعملاء محدّثة.

## تنبيه عن البيانات القديمة

السعر لا يظهر للنموذج قبل مزامنته مرة واحدة بعد هذا التحديث. ورصيد الصناديق يعتمد على مجموعي التسليم والرجوع المسجلين للعميل؛ إذا لم تُدخلا في إدارة العملاء فلن يخمّن النظام الرقم. كما أن فواتير الآجل القديمة لا تكفي وحدها لمعرفة الدين بعد السداد، لأن هذا الإصدار لا يملك دفتر دفعات متكاملًا.

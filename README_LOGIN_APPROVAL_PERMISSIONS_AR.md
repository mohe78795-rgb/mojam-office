# تحديث تسجيل الدخول واعتماد العاملين والصلاحيات

## ما الذي تغيّر؟

### 1. تسجيل الدخول مرة واحدة في تطبيق Android

- يحفظ التطبيق رمز التجديد داخل `SharedPreferences` الخاصة بالتطبيق، ولا يرسله إلى JavaScript.
- عند انتهاء رمز الدخول القصير (30 دقيقة)، يجدّد التطبيق الجلسة تلقائياً في الخلفية ويعيد الطلب، من دون مطالبة العامل بإعادة تسجيل الدخول.
- مدة رمز التجديد المنزلقة 90 يوماً: يتجدد أجلها عند استخدام التطبيق بنجاح. إذا مرّت 90 يوماً بلا استخدام، أو ألغى المدير الجلسة/حظر الحساب، يلزم تسجيل الدخول من جديد.
- إعادة تثبيت التطبيق أو مسح بياناته تحذف رمز التجديد؛ حدّث التطبيق فوق النسخة السابقة ولا تمسح بياناته إذا أردت الاحتفاظ بالجلسة.

### 2. زر تسجيل الخروج

أُضيف زر **تسجيل الخروج** إلى ترويسة المتجر. عند الضغط عليه يحاول التطبيق إبطال الجلسة على الخادم، ثم يمسح رمز الدخول ورمز التجديد من الجهاز ويعيد عرض بوابة الدخول. إذا كان الجهاز بلا اتصال، تُمسح الرموز محلياً، لكن لا يمكن ضمان وصول طلب الإبطال إلى الخادم حتى يعود الاتصال.

### 3. اعتماد العامل وتعيين صلاحياته معاً

في إدارة العاملين، زر الطلب المعلّق أصبح **اعتماد وتحديد الصلاحيات**. يختار المدير الدور، ويراجع مربعات الصلاحيات، ثم يحفظ؛ لا يصبح الحساب نشطاً قبل حفظ الاختيارين معاً. بعد الاعتماد، يستطيع العامل تسجيل الدخول تلقائياً من صفحة الانتظار.

تغيير الدور يضع مجموعة صلاحيات بداية قابلة للتعديل:

- **عامل مبيعات:** عرض/إنشاء الفواتير وعرض العملاء.
- **محاسب:** الفواتير والعملاء والتقارير بحسب مربعات الاختيار.
- **استقبال شحنات:** عرض/إضافة/تعديل الشحنات وعرض العملاء.
- **مشرف رسائل:** قراءة الرسائل وتوليد الردود وإرسال SMS وعرض العملاء.
- **مشاهد تقارير:** عرض الفواتير والشحنات والعملاء وتصدير التقارير.
- **مدير:** صلاحية إدارة كاملة؛ تظهر رسالة تأكيد قبل الحفظ.

مربعات الاختيار هي الصلاحيات الفعلية؛ يمكن تعديلها بعد اختيار الدور. يمكن فتح **الصلاحيات** لمستخدم معتمد لتغييرها لاحقاً.

### 4. تطبيق الصلاحيات على الخادم

تُرفض الطلبات غير المصرح بها من الخادم، وليس من إخفاء الأزرار فقط. المدير/المالك يتجاوزان فحوص الصلاحيات. أمثلة:

| الصلاحية | المسارات المحمية |
|---|---|
| `invoices.view` | قراءة مزامنة يوم العمل |
| `invoices.create` | حفظ مزامنة يوم العمل وحجز رقم فاتورة |
| `customers.view` | قراءة العملاء |
| `customers.edit` | حفظ/تعديل العملاء |
| `sms.read` | قراءة الرسائل والمحادثات وإعدادات الرسائل |
| `sms.generate_reply` | توليد الردود وتحليل الطلبات والرسائل الواردة الخلفية |
| `sms.send` | إرسال SMS وتسجيل الرسالة الصادرة |

في تطبيق Android، يتحقق جسر الهاتف من صلاحية `sms.read` أو `sms.send` من الخادم قبل قراءة الرسائل أو الإرسال المحلي. كما لا يرسل الرد الآلي من الشريحة إلا إذا كانت صلاحية الإرسال ممنوحة للعامل.

## الملفات

- `server/src/server.js` — تجديد الجلسة، إبطال تسجيل الخروج، اعتماد العامل مع الدور والصلاحيات، وفحوص الصلاحيات على API.
- `public/index.html` — الاستعادة التلقائية للجلسة، زر الخروج، شاشة اعتماد العامل، وربط طلبات الواجهة بالمصادقة.
- `android-java/WebInterface.java` — جسر Android الذي يجدّد جلسة الخادم ويمسح الرموز عند تسجيل الخروج.

## نشر الخادم من Termux

شغّل الأمر وأنت داخل مجلد مستودع Git (أو أحد مجلداته)، بعد تنزيل ZIP إلى مجلد Downloads. يتوقف الأمر إذا لم يكن داخل المستودع أو كان هناك تعديل محلي على الملفات نفسها:

```bash
set -eu
ZIP="$HOME/storage/downloads/mojam_login_approval_permissions_update.zip"
ROOT="$(git rev-parse --show-toplevel 2>/dev/null)" || {
  echo "افتح Termux داخل مجلد مستودع المشروع ثم أعد الأمر."
  exit 1
}
cd "$ROOT"
test -d public && test -d server || {
  echo "المجلد الحالي ليس جذر المشروع الذي يحتوي public وserver."
  exit 1
}
test -f "$ZIP" || {
  echo "لم أجد الحزمة: $ZIP"
  exit 1
}
git diff --cached --quiet || {
  echo "توجد تغييرات مضافة مسبقاً؛ احفظها أو أزلها قبل المتابعة."
  exit 1
}
if git status --porcelain -- server/src/server.js public/index.html README_LOGIN_APPROVAL_PERMISSIONS_AR.md | grep -q .; then
  echo "توجد تغييرات محلية على ملفات التحديث؛ لن أستبدلها. افحصها أولاً."
  exit 1
fi
unzip -o "$ZIP" -d .
node --check server/src/server.js
git diff --check -- server/src/server.js README_LOGIN_APPROVAL_PERMISSIONS_AR.md
git add server/src/server.js public/index.html README_LOGIN_APPROVAL_PERMISSIONS_AR.md
git diff --cached --check
git diff --cached --stat
git commit -m "Persist Android sessions and enforce employee permissions"
git push origin "$(git branch --show-current)"
```

بعد الدفع، انتظر اكتمال النشر في Render.

## تحديث مشروع Android Studio

1. انسخ `android-java/WebInterface.java` فوق ملف `WebInterface.java` في حزمة Java المطابقة لـ `com.Yaaqoub.Market.Card` داخل مشروع Android Studio. لا تستبدل `MainActivity.java` بهذا الملف.
2. انسخ الواجهة المحدّثة إلى أصل WebView الذي يستخدمه مشروعك. الكود الحالي يحمّل `https://app.local/index.html` من مجلد الأصول `www/`، ويُفضّل الملف المشفّر (`index.enc`) على `index.html` العادي. لذلك إن كان `www/index.enc` موجوداً، أعد توليده بأداة/خطوة التشفير نفسها المستخدمة في مشروعك؛ مجرد تحديث `public/index.html` على Render لن يغيّر الصفحة المضمّنة في APK.
3. نفّذ Gradle Sync ثم ابنِ APK ووقّعه بمفتاح التوقيع نفسه للنسخة المثبّتة. ثبّت التحديث فوق التطبيق الحالي، ولا تحذف التطبيق أو تمسح بياناته إن أردت إبقاء رمز الجلسة المحفوظ.

لم يُنشأ APK هنا لأن ملفات مشروع Android Studio الكاملة وملفات الأصول/التشفير غير موجودة في المواد المتاحة؛ الملف Java والواجهة جاهزان للدمج في مشروعك.

## اختبار آمن بعد النشر

1. حدّث APK، سجّل الدخول مرة واحدة، ثم أغلق التطبيق وافتحه؛ يفترض أن يستعيد الجلسة دون إظهار نموذج الدخول.
2. اترك التطبيق مفتوحاً بعد انتهاء رمز الوصول القصير؛ يفترض أن يجدّد الجلسة تلقائياً.
3. جرّب زر **تسجيل الخروج**؛ يجب أن تظهر بوابة الدخول مجدداً. سجّل الدخول مرة أخرى للتأكد.
4. من حساب المدير، افتح إدارة العاملين واعتمد حساباً تجريبياً مع دور وصلاحيات محددة. تأكد أن الحساب يظهر نشطاً وأن العامل يدخل تلقائياً.
5. جرّب صلاحية `sms.read` و`sms.send` بحساب تجريبي. اترك **الإرسال التلقائي** متوقفاً في الاختبار الأول لتجنب إرسال SMS حقيقية.

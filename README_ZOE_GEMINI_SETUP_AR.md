# تفعيل «زوع» — Gemini 3.5 Flash Lite

## التغيير

اعتمدت الواجهة والخادم النموذج الرسمي `gemini-3.5-flash-lite`، وهو معرّف النموذج المستقر الذي تسرده [بطاقة Google الرسمية](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite). أصبح `/api/chat` يستدعي Google Gemini فعلًا بدل الرد الجاهز، ويرسل الطلب من الخادم فقط. تتطلب الدردشة جلسة دخول صالحة، وتعرض الواجهة حالة إعداد المفتاح وأخطاء Google بدل رسالة نجاح مضللة. لا يُرسل رقم هاتف العميل إلى Gemini؛ تُرسل رسالة العميل والاسم، وقد تُرسل أرقام الرصيد والصناديق عند توفرها لتكوين الرد.

لا تحتوي الحزمة على مفتاح API. لا تضع المفتاح في `public/index.html` ولا ترفعه إلى GitHub ولا ترسله في رسالة.

## إضافة المفتاح في Render

1. أنشئ أو افتح مفتاح Gemini من [Google AI Studio](https://aistudio.google.com/apikey).
2. افتح خدمة API التي تستضيف `https://mojam-office.onrender.com` في Render، ثم **Environment**.
3. أضف متغيرًا باسم `GEMINI_API_KEY` وضع المفتاح في خانة القيمة، ثم احفظ. أعد النشر أو انتظر إعادة تشغيل الخدمة حتى تقرأ المتغير.
4. إذا كنت تختبر محليًا، ضع `GEMINI_API_KEY=...` في `server/.env` بجوار مجلد `src`، وليس في `server/src/.env`. لا تضف ملف `.env` إلى Git.

**مهم للمفاتيح:** توثيق Google الحالي يرفض مفاتيح API القياسية غير المقيّدة؛ استخدم مفتاح تفويض، أو قيّد المفتاح القياسي على Gemini API فقط. إذا ظهر `مفتاح Gemini غير صالح أو غير مخوّل` فتحقق من نوع المفتاح وقيوده ومن تفعيل Gemini API والحصة للمشروع. راجع [تعليمات مفاتيح Gemini الرسمية](https://ai.google.dev/gemini-api/docs/api-key).

## رفع الكود من Termux

من جذر مشروع GitHub، وليس من مجلد `server`:

```bash
cd ~/projects/mojam/مكتب_معجم_حزمة || exit 1
unzip -o /storage/emulated/0/Download/mojam_zoe_gemini_35_update.zip -d .
git status --short
```

تأكد من ظهور الملفات الأربعة التالية، ثم ارفعها:

```bash
git add public/index.html public/invoice-manual-cards.js server/src/server.js server/src/gemini.js
git commit -m "Connect Zoe to Gemini 3.5 Flash Lite"
git push origin main
```

تتضمن الحزمة ملف الفاتورة اليدوي لأن `index.html` الحالي يحمّله. لا تتضمن تعديلًا على قاعدة البيانات ولا تحتاج إلى تشغيل `seed-admin`.

## التحقق بعد النشر

1. انتظر اكتمال نشر Render وافتح التطبيق من جديد.
2. في إعدادات النموذج، يفترض أن ترى **زوع — مبني على Gemini 3.5 Flash Lite**. وتظهر حالة المفتاح أسفل الاختيار.
3. جرّب توليد رد يدويًا أولًا. تظهر رسالة نجاح فقط إذا عاد رد فعلي من Gemini. إذا تعذّر الاتصال، تعرض الواجهة الرد المحلي الاحتياطي مع تنبيه بضرورة مراجعته قبل إرساله.
4. لا تفعّل الإرسال التلقائي قبل نجاح الاختبار اليدوي ومراجعة إعدادات الأتمتة.

الأخطاء الشائعة تظهر برسائل محددة: مفتاح غير صالح أو غير مخوّل، تجاوز الحصة أو حد الطلبات، تعذر الوصول من Render، أو عدم إعداد `GEMINI_API_KEY`. لا تضع قيمة المفتاح في السجلات أو الرسائل.

# تحديث ترقيم الفواتير واسم البائع

## ما الذي يتغير؟

- يحصل كل جهاز/عامل بعد تسجيل الدخول على رقم فاتورة يحجزه الخادم ذريًا من MongoDB؛ يبدأ التسلسل بـ `00000` ثم `00001` وهكذا.
- إذا صادف رقم قديم محفوظ، يتجاوزه الخادم. الأرقام المحجوزة لا تُعاد للاستخدام؛ لذلك قد توجد فجوات إذا أُلغيت فاتورة أو أُغلق النموذج قبل الحفظ، وهذا مقصود لمنع التكرار.
- رقم الفاتورة للقراءة فقط، ويُحدّث تلقائيًا بعد حفظ كل فاتورة.
- يُحفظ اسم المستخدم المصادق عليه كاسم البائع في بيانات الفاتورة، ويظهر أسفل فاتورة PDF والطباعة الحرارية.
- لا يلزم تغيير `.env` أو إضافة مفتاح جديد أو تشغيل ترحيل يدوي. يستخدم الخادم مجموعة MongoDB `number_sequences` عبر تحديث ذري.

## الملفات المستبدلة

استبدل الملفات التالية من جذر المشروع، وأضف ملف الخادم الجديد:

- `public/index.html`
- `public/invoice-manual-cards.js`
- `server/src/server.js`
- أضف `server/src/invoice-numbering.js`

لا تستبدل ملف `.env`، ولا تضفه إلى GitHub. احتفظ ببقية ملفات Gemini/Mongo الحالية كما هي.

## الرفع من Termux

من جذر مستودع `mojam-office`، بعد فك الحزمة فوق المشروع:

```bash
git add public/index.html public/invoice-manual-cards.js \
  server/src/server.js server/src/invoice-numbering.js \
  README_INVOICE_NUMBER_SELLER_AR.md

git diff --cached --check
git status --short

git commit -m "Add unique invoice numbering and seller name"
git push origin main
```

تأكد أن `git status --short` لا يعرض أي ملف `.env` قبل الرفع. بعد نجاح `git push`، راقب نشر Render حتى تصبح الخدمة Live، ثم افتح التطبيق وسجّل الدخول؛ ينبغي أن يظهر الرقم `00000` أو أول رقم تالٍ متاح.

## ملاحظة عن الفواتير السابقة

الفواتير الجديدة تحفظ اسم البائع تلقائيًا. الفواتير القديمة التي لا تحتوي اسم بائع محفوظًا ستعرض «غير مسجل» عند إعادة الطباعة، ولا يمكن استنتاج اسم منشئها بأمان من بياناتها القديمة.

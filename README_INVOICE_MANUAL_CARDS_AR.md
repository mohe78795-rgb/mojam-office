# تحديث الفاتورة — اختيار كرت يدوي وصناديق لكل صنف

## ما الذي يتغير؟

- تصميم نموذج الفاتورة يطابق المرجع المرفق: جدول أصناف ملوّن، بيانات العميل، وثلاث بطاقات إجمالية للدجاج والصناديق والمبلغ.
- اضغط على اسم الصنف لاختيار **كرت الشحنة / المورد / المزرعة** الذي ستُخصم منه الكمية. يظهر المتبقي المتاح لكل كرت.
- لا يوزّع هذا التحديث الكمية تلقائيًا على FIFO؛ كل سطر يُحفظ مربوطًا بالكرت الذي اخترته. إذا اخترت «المخزون العام» فسيخصم من رصيد المخزون العام فقط، ولن يسحب من كروت الشحنات.
- زر السهم يضيف سطرًا آخر من الصنف نفسه؛ يمكن تخصيص كل سطر لكرت مختلف.
- أدخل **عدد الصناديق الفارغة بجانب كل صنف**. يُحفظ عدد كل سطر، ويظهر مجموع الصناديق في ملخص الفاتورة والتكدس ونسخة الطباعة.
- يبقى خيار حفظ الفاتورة بالتكدس مع الطباعة الحرارية أو من دون طباعة. وتظل إعدادات الطابعة والرول الحالية كما هي.
- لم تتغير واجهة الدخول أو صفحة إدارة العاملين، ولم يتغير رابط API: `https://mojam-office.onrender.com`.

## الملفات في الحزمة

- `public/index.html`: ربط الملف الجديد، وتنسيق الفاتورة.
- `public/invoice-manual-cards.js`: اختيار كرت الشحنة، تكرار سطر الصنف، الصناديق لكل صنف، والحفظ والطباعة.

لا يحتاج هذا التحديث إلى تعديل `server/src/server.js` أو متغيرات Render أو تشغيل `seed-admin`؛ الحقول تُحفظ ضمن بيانات بنود اليومية الموجودة.

## التثبيت والرفع من Termux

1. انقل `mojam_office_manual_card_invoice_update.zip` إلى مجلد تنزيلات الهاتف.
2. انتقل إلى جذر مشروعك المرتبط بمستودع GitHub، وليس مجلد `server`:

   ```bash
   cd ~/projects/mojam/مكتب_معجم_حزمة || exit 1
   ```

3. أنشئ نسختين احتياطيتين ثم فك الحزمة في جذر المشروع:

   ```bash
   cp public/index.html public/index.html.backup-$(date +%Y%m%d-%H%M%S)
   cp public/invoice-manual-cards.js public/invoice-manual-cards.js.backup-$(date +%Y%m%d-%H%M%S) 2>/dev/null || true
   unzip -o /storage/emulated/0/Download/mojam_office_manual_card_invoice_update.zip -d .
   ```

4. اعرض الملفات المتغيرة وتأكد أن الملفين المطلوبين موجودان:

   ```bash
   git status --short
   ls -l public/index.html public/invoice-manual-cards.js
   ```

5. ارفع التعديل إلى GitHub من جذر المشروع:

   ```bash
   git add public/index.html public/invoice-manual-cards.js
   git commit -m "Use manual shipment cards and per-item empty crates"
   git push origin main
   ```

6. انتظر اكتمال النشر التلقائي في Render، ثم حدّث التطبيق تحديثًا قويًا أو امسح ذاكرة الصفحة المؤقتة.

## اختبار بعد النشر

1. افتح **الفواتير** وأدخل كمية لصنف.
2. اضغط اسم الصنف، واختر كرت المورد الصحيح. أضف سطرًا آخر بالسهم إذا كان الصنف موزعًا بين كرتين، ثم اختر الكرت الآخر لذلك السطر.
3. أدخل الصناديق الفارغة بجانب كل صنف. تحقق من مجموع الصناديق والمبلغ في البطاقات أسفل الجدول.
4. اختر **حفظ في التكدس بدون طباعة**، وافتح الفاتورة المحفوظة للتحقق من كمية كل صنف وكرت الشحنة وعدد الصناديق.
5. للطباعة، اختبر خيار **حفظ في التكدس مع طباعة حرارية** بعد اختيار الطابعة والرول من مركز الطابعات.

إذا كان الرصيد موجودًا في كروت الشحنات وليس في المخزون العام، اختر كرتًا للصنف قبل الحفظ؛ لا يختار النظام الكرت تلقائيًا في هذا التحديث.
